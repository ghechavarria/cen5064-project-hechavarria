# ADR-010: Validate input and contain failures at the tier edges

**Date:** 2026-10-18
**Status:** accepted

## Context

A QA pass after the midterm tried bad input and bad conditions on purpose, and several of them broke the app or misled the owner:

- A mistyped ISBN went to both book sources and came back as "No book found", even though the number itself was wrong.
- The same book typed as an ISBN-10 and later scanned as its ISBN-13 barcode was stored as two different books, breaking the "a duplicate adds a copy" rule.
- A book source that never answered left the scan spinning forever, and any network problem was shown as "Could not update the library."
- A half-written or hand-edited browser save made `JSON.parse` throw at start-up, so the app never loaded.
- In SQLite the ISBN was unique across all owners, and saving looked a book up by ISBN alone, so a second owner's save could overwrite the first owner's row.

## Decision

Each tier checks what crosses into it, and each kind of failure gets one type the screens can explain:

- **Domain:** `Isbn.parse` accepts only an ISBN-13 (978/979) or ISBN-10 whose check digit is correct, and throws `InvalidIsbnError` otherwise. `LookupIsbnUseCase` and `ScanBookUseCase` call it first, so a typo never reaches the network or the store. It returns the ISBN-13 even for an ISBN-10, so one book has one key however it was entered, and the duplicate-scan rule holds; rows saved under an ISBN-10 are re-keyed on load, and a book stored both ways becomes one book with its copies added together.
- **Service port:** `BookSourceUnavailableError` is the one error a book source may throw for "could not answer". `Http` raises it for a timeout (15 s), any error status (including 429 rate limits), being offline, or JSON that isn't an object. Its message never repeats the request URL, so the Google key can't leak into it. The view model shows it in red with a retry hint.
- **Data:** `BookRowMapper.withDefaults` turns any stored row, old or damaged, into a valid `BookRow`: unknown enum values fall back to safe defaults (an unknown shelf becomes Wanted, never Owned), and rows without an owner or ISBN are skipped (`isUsable`). `JsonBookRepository` keeps an unreadable save under a backup key and starts empty instead of crashing. SQLite rows are unique per `(owner_id, isbn)`; an older database is rebuilt once, in a transaction, to the new constraint.

## Consequences

Every failure the QA pass found now has a test (`tests/resilience.test.ts`, `tests/persistence.test.ts`). SQLite is tested against a real database (Node's built-in `node:sqlite`), including an upgrade from the first-release schema. The cost is a stricter scanner: a non-book barcode or an ISBN with a wrong check digit is refused with a message instead of being looked up. The one-time rebuild of an old SQLite table runs on the first start after the update.
