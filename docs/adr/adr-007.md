# ADR-007: MVVM presentation with an observable view model

**Date:** 2026-10-05
**Status:** accepted

## Context

`App.tsx` had grown into one large component holding every popup flag, scan step and shelf change in React hooks. That logic could only be tested by rendering the UI, and the course asks for classes that bundle data with behavior. Presentation must still never touch a repository.

## Decision

Move all screen state and flows into `LibraryAppModel`, a plain class that extends a reusable `Observable` base class. React subscribes through one hook (`useObservable`) and components only render and forward taps. `LibraryController` is the model's bridge to the Service use cases, and device features sit behind interfaces (`CoverCamera`).

## Consequences

Every user flow (scan, gift, move, delete, cover photo) is unit-tested without React (`tests/appModel.test.ts`). Components stay small and reusable. Adding a screen means adding model methods first, then a thin view. The cost is one extra layer to read when tracing a tap.
