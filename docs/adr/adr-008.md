# ADR-008: Design system — tokens, stylesheet imports, shared UI building blocks

**Date:** 2026-10-10
**Status:** accepted

## Context

The course requires stylesheets to be imports, not inline in components, and no duplicated code. Early screens repeated colors, sizes and press logic in each file, and the look drifted between screens. The app must still run in the free Expo Go client, so no custom native modules.

## Decision

- `presentation/styles/theme.ts` holds every design token: colors, spacing, radii, type sizes, text roles (one font family, Outfit, in four weights), and shared surfaces (card, panel, cover).
- Each component imports its own `<name>.styles.ts`; no colors or sizes are typed in components.
- Shared building blocks replace copies: `Tappable` (all tap feedback), `TextField`, `BookCover`, `CoverBackdrop`, `Logo`, `Reveal`.
- UI polish uses only modules bundled in Expo Go: `expo-font`, `expo-image`, `expo-linear-gradient`, `expo-haptics`.

`tests/architecture.test.ts` fails the build if a component creates a stylesheet or an inline style object.

## Consequences

One change to a token restyles the whole app, and every screen looks and behaves alike. New screens reuse the building blocks instead of styling from scratch. Respecting the phone's Reduce Motion setting and WCAG AA contrast is handled once, in the shared pieces. Anything that needs a custom native build (gesture or animation libraries) stays out while the project targets Expo Go.
